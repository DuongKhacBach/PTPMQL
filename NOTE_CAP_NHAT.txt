- Kiến thức & Định nghĩa cơ bản:
  * Mô hình MVC (Model - View - Controller):
    - Model: Đại diện cho dữ liệu, các lớp đối tượng và quy tắc nghiệp vụ (business logic).
    - View: Giao diện người dùng (UI), hiển thị dữ liệu ra màn hình (sử dụng cú pháp Razor .cshtml).
    - Controller: Bộ phận trung gian tiếp nhận yêu cầu (HTTP Request), tương tác với Model và chọn View tương ứng để trả kết quả (Response).
  * Action: Phương thức (Method) nằm trong Controller xử lý một chức năng cụ thể (ví dụ: Index(), Details(), Create()).
  * Layout (_Layout.cshtml): Template khung giao diện dùng chung (header, menu, footer) cho toàn bộ website, giúp code giao diện không bị lặp lại.

  + Tùy biến định tuyến (Custom Route: /thong-tin/trang-chu).

- Kiến thức & Định nghĩa cơ bản:
  * Model Binding: Cơ chế tự động chuyển đổi dữ liệu từ HTTP Request (Form inputs, Query string, Route parameters) thành các kiểu dữ liệu và đối tượng C# tương ứng.
  * HTTP GET vs HTTP POST:
    - HTTP GET: Phương thức dùng để yêu cầu dữ liệu từ server (ví dụ: mở trang hiển thị form trống). Dữ liệu đính kèm trên thanh địa chỉ URL.
    - HTTP POST: Phương thức dùng để gửi dữ liệu từ form lên server để xử lý/lưu trữ. Dữ liệu được giấu trong phần thân (Body) của request, an toàn hơn và truyền được nhiều dữ liệu.
  * Tag Helpers (asp-for, asp-action, asp-controller): Cú pháp mở rộng của Razor trong ASP.NET Core giúp liên kết các trường input của HTML trực tiếp với thuộc tính trong Model C#.
  * Routing (Định tuyến): Cơ chế ánh xạ đường dẫn URL mà người dùng truy cập tới Controller và Action tương ứng để thực thi.

      + Thứ tự nhúng CSS: Phải nhúng bootstrap.min.css TRƯỚC, rồi mới nhúng các file CSS tự viết (site.css, custom.css) để có thể ghi đè (override) style theo ý muốn.

  * Tác dụng của việc Tách file CSS và Nhúng vào Layout (_Layout.cshtml):
    - Tái sử dụng & Tính nhất quán: Khai báo 1 lần tại _Layout.cshtml, mọi View con (Home, Demo, Student...) đều tự động áp dụng chung bộ nhận diện giao diện (font chữ, màu sắc, nút bấm).
    - Tối ưu hiệu năng (Browser Caching): File .css tách biệt được trình duyệt lưu vào bộ nhớ đệm (Cache), khi người dùng chuyển trang không cần tải lại CSS -> tốc độ tải trang cực nhanh.
    - Dễ bảo trì & Quản lý module: Tách bạch rõ ràng giữa site.css (reset/font chữ nền tảng) và custom.css (tùy biến màu sắc, đổ bóng, hiệu ứng). Khi cần đổi giao diện toàn web chỉ cần sửa 1 nơi duy nhất.
    - Thuộc tính asp-append-version="true": Tự động sinh mã băm phiên bản (hash version) giúp trình duyệt tự cập nhật file CSS mới ngay khi có chỉnh sửa mà không bị dính cache cũ.

  * Thư mục wwwroot (Web Root):
    - Khái niệm: Thư mục gốc công khai duy nhất lưu trữ các tệp tài nguyên tĩnh (Static Files: CSS, JS, hình ảnh, thư viện bên thứ 3).
    - Tính bảo mật: Toàn bộ mã nguồn C#, Controllers, Models, Views nằm ngoài wwwroot đều được máy chủ bảo vệ an toàn, người dùng không thể truy cập trực tiếp qua URL.
    - Cấu hình bắt buộc: Cần có app.UseStaticFiles(); trong Program.cs để máy chủ kích hoạt tính năng phục vụ tệp tĩnh từ wwwroot.

  * Khái niệm ORM & Entity Framework Core:
    - ORM (Object-Relational Mapping): Kỹ thuật ánh xạ bảng cơ sở dữ liệu thành các lớp (Class) đối tượng trong C#, giúp thao tác dữ liệu qua code mà không cần viết câu lệnh SQL thủ công.
    - Entity Framework Core (EF Core): Thư viện ORM chính thức và mạnh mẽ nhất cho nền tảng .NET.
    - CRUD: 4 thao tác quản lý dữ liệu cốt lõi (Create - Tạo, Read - Đọc, Update - Cập nhật, Delete - Xóa).

- Ngày cập nhật: 17/09/2026
- Nội dung tóm tắt:
  + Cấu hình kết nối Cơ sở dữ liệu SQLite trong dự án ASP.NET Core MVC theo phương pháp Code-First.
  + Thực hiện quy trình 7 bước chuẩn:
    * Bước 1. Cài đặt các package cần thiết cho project:
      - Cài đặt dotnet tools toàn cục: dotnet-aspnet-codegenerator, dotnet-ef.
      - Cài đặt các thư viện NuGet: Microsoft.EntityFrameworkCore.Design, Microsoft.EntityFrameworkCore.Sqlite, Microsoft.VisualStudio.Web.CodeGeneration.Design, Microsoft.EntityFrameworkCore.SqlServer, Microsoft.EntityFrameworkCore.Tools.
    * Bước 2. Thiết lập kết nối CSDL trong appsettings.json:
      - Khai báo ConnectionStrings với chuỗi kết nối "DefaultConnection": "Data Source=App.db; Cache=Shared".
    * Bước 3. Tạo file ApplicationDbContext:
      - Tạo thư mục Data và lớp ApplicationDbContext kế thừa DbContext.
      - Khai báo DbSet<Person> Person { get; set; } để ánh xạ bảng dữ liệu vào CSDL.
    * Bước 4. Cấu hình kết nối CSDL trong Program.cs:
      - Đăng ký DbContext với DI Container qua builder.Services.AddDbContext<ApplicationDbContext>(...).
      - Chỉ định sử dụng SQLite qua options.UseSqlite(...).
    * Bước 5. Tạo class trong Model:
      - Tạo lớp Person trong thư mục Models với các thuộc tính: PersonId (khóa chính [Key]), FullName, Address.
      - Sử dụng Data Annotations ([Table("Persons")]) để định danh bảng tương ứng trong CSDL.
    * Bước 6. Sử dụng Migrations để quản lý phiên bản CSDL:
      - Chạy lệnh: dotnet ef migrations add Create_table_Person để sinh mã khởi tạo bảng Persons.
    * Bước 7. Cập nhật thay đổi CSDL:
      - Chạy lệnh: dotnet ef database update để áp dụng migration, tự động sinh ra file CSDL SQLite App.db.
      - Cài đặt và sử dụng extension SQLite Viewer trong IDE để xem trực quan bảng dữ liệu.

- Kiến thức & Định nghĩa cơ bản:
  * Phương pháp Code-First:
    - Cách tiếp cận xây dựng mã nguồn (C# Class Model) trước, sau đó Entity Framework Core tự động sinh ra cấu trúc bảng và cơ sở dữ liệu (Database) tương ứng.
  * DbContext & DbSet:
    - DbContext: Cầu nối trung gian đại diện cho phiên làm việc với cơ sở dữ liệu, quản lý theo dõi thay đổi (Change Tracking), lưu trữ và truy vấn dữ liệu.
    - DbSet<TEntity>: Đại diện cho một tập hợp thực thể (bảng) trong CSDL, cho phép thực hiện các thao tác CRUD (Create, Read, Update, Delete).
  * Data Annotations:
    - Các thuộc tính đặt trước class/property (như [Table], [Key], [Required], [MaxLength]) để cấu hình quy tắc và ràng buộc dữ liệu cho bảng CSDL trực tiếp trên Model.
  * Connection String (Chuỗi kết nối):
    - Chuỗi thông số cấu hình cung cấp cho ứng dụng biết loại CSDL, vị trí lưu trữ file (Data Source=App.db), và chế độ chia sẻ bộ nhớ (Cache=Shared).
  * EF Core Migrations:
    - Cơ chế quản lý các phiên bản thay đổi của cấu trúc CSDL theo thời gian (tương tự như Git cho CSDL), giúp đồng bộ và nâng cấp CSDL an toàn mà không làm mất dữ liệu.

    * 4. School (Trường học)
  + Chi tiết các thành phần thực hiện:
    * 1. Xây dựng & Tối ưu PersonController:
      - Áp dụng Dependency Injection (DI) để tiêm ApplicationDbContext vào Controller.
      - Action Index (Read): Truy vấn bất đồng bộ danh sách Person từ CSDL qua await _context.Person.ToListAsync().
      - Action Create (GET/POST): Nhận và lưu 4 trường dữ liệu vào SQLite qua _context.Add(person) và await _context.SaveChangesAsync().
      - Action Edit (GET/POST): Tìm kiếm bản ghi theo id qua FindAsync(id), hiển thị form chỉnh sửa và cập nhật 4 trường qua _context.Update(person).
      - Action Delete (GET/POST): Hiển thị chi tiết 4 trường và thực thi xóa bản ghi khỏi SQLite qua _context.Person.Remove(person).
      - Áp dụng [ValidateAntiForgeryToken] trên tất cả các Action POST để chống tấn công CSRF.
    * 2. Xây dựng 4 View CRUD trong thư mục Views/Person/:
      - Index.cshtml: Bảng dữ liệu Bootstrap 5 hiển thị đầy đủ 4 cột (ID, Họ tên, Địa chỉ, Trường học) kèm các nút Sửa, Xóa.
      - Create.cshtml: Form thêm mới 4 trường với Razor Tag Helpers (asp-action, asp-for, asp-validation-for).
      - Edit.cshtml: Khóa chính PersonId được đặt readonly để bảo vệ toàn vẹn dữ liệu, cho phép sửa FullName, Address, School.
      - Delete.cshtml: Màn hình xác nhận hiển thị đầy đủ 4 thông tin trước khi xóa, truyền ID ngầm qua <input type="hidden" asp-for="PersonId" />.
    * 3. Cơ sở dữ liệu & Tự động Migration:
      - Tạo Migration Add_School_To_Person và bổ sung tự động dbContext.Database.Migrate() trong Program.cs để CSDL SQLite App.db tự động cập nhật cấu trúc bảng.
    * 4. Tinh gọn & Thống nhất toàn bộ Website:
      - Dọn dẹp các file cũ/dư thừa (StudentController.cs, Models/Student.cs, Views/Student).
      - Đồng bộ thanh menu Navbar (_Layout.cshtml) và các nút bấm tại trang chủ (Home/Index.cshtml) trỏ trực tiếp đến trang Quản lý Dữ liệu (/Person).

- Kiến thức & Định nghĩa cơ bản:
  * Mối liên hệ giữa CSDL/DbContext và CRUD:
    - CRUD (Create - Read - Update - Delete) là 4 thao tác nghiệp vụ cơ bản mà người dùng tương tác trên giao diện.
    - ApplicationDbContext là cầu nối ORM (Entity Framework Core) chuyển đổi các phương thức C# thành các câu lệnh SQL tương ứng (INSERT, SELECT, UPDATE, DELETE) và ghi trực tiếp vào file vật lý App.db.
    - Nếu không có DbContext/CSDL: Dữ liệu chỉ lưu tạm trên RAM và bị mất sạch khi khởi động lại ứng dụng.
    - Nếu không có CRUD: CSDL chỉ là file tĩnh nằm im trên đĩa cứng, người dùng không thể xem hay quản trị dữ liệu.
  * Dependency Injection (DI) trong Controller:
    - Cơ chế cung cấp các phụ thuộc (Dependencies như DbContext) từ bên ngoài vào Controller thông qua hàm khởi tạo (Constructor), giúp giảm sự phụ thuộc chặt chẽ (tight coupling) và tăng tính module, dễ kiểm thử.
  * Tag Helpers & Model Binding:
    - Tag Helpers (asp-for, asp-action, asp-route-id): Giúp mã HTML sạch hơn, tích hợp chặt chẽ với C# Model.
    - Model Binding: Tự động gom dữ liệu từ Form gửi lên (POST) và ép kiểu thành đối tượng Model Person trong C# tương ứng.
  * Bảo mật CSRF (Cross-Site Request Forgery):
    - Kỹ thuật tấn công giả mạo yêu cầu từ người dùng đã xác thực. Thuộc tính [ValidateAntiForgeryToken] và mã token tự sinh trong form giúp máy chủ xác minh yêu cầu gửi đến là hợp lệ từ chính form của hệ thống.

    - Công cụ CLI của Microsoft giúp tự động sinh mã nguồn Controller và Views CRUD dựa trên Model và DbContext có sẵn, giúp tăng tốc độ phát triển ứng dụng.
    - Cú pháp chuẩn: dotnet aspnet-codegenerator controller -name EmployeeController -m Employee -dc DemoMVC.Data.ApplicationDbContext --relativeFolderPath Controllers --useDefaultLayout --referenceScriptLibraries --databaseProvider sqlite
  * Data Annotations:
    - Bộ thuộc tính siêu dữ liệu (Metadata Attributes) đặt trên các thuộc tính của Model C# để cấu hình ràng buộc CSDL và quy tắc xác thực dữ liệu:
      + [Key]: Định danh trường làm khóa chính (Primary Key).
      + [Display(Name = "...")]: Định cấu hình nhãn hiển thị thân thiện trên giao diện View.
      + [Required(ErrorMessage = "...")]: Ràng buộc trường bắt buộc phải nhập dữ liệu.
      + [StringLength(max, MinimumLength = min)]: Ràng buộc độ dài chuỗi ký tự.
      + [Range(min, max)]: Ràng buộc giá trị số nằm trong khoảng hợp lệ.
      + [Table("...")]: Ánh xạ tên bảng tương ứng trong CSDL.
    - Cơ chế kiểm thực:
      + Client-side Validation: Trình duyệt tự động kiểm tra lỗi thông qua jQuery Validation mà không cần tải lại trang.
      + Server-side Validation: Máy chủ kiểm tra an toàn qua ModelState.IsValid trong Action HttpPost trước khi lưu vào CSDL.
  * LINQ (Language Integrated Query):
    - Cú pháp truy vấn dữ liệu đồng nhất được tích hợp trực tiếp vào ngôn ngữ C#, cho phép lọc, sắp xếp, biến đổi dữ liệu trên các tập hợp (Collections, Arrays) và CSDL (qua EF Core).
    - Các toán tử LINQ cốt lõi:
      + AsQueryable() / AsNoTracking(): Tối ưu hóa truy vấn dạng hoãn (Deferred Execution), câu lệnh SQL chỉ thực sự gửi tới SQLite khi gọi ToListAsync().
      + Where(condition): Lọc danh sách theo biểu thức điều kiện (tương đương WHERE trong SQL).
      + Contains(keyword): Kiểm tra chuỗi con (tương đương LIKE %keyword% trong SQL).
      + OrderBy() / OrderByDescending(): Sắp xếp danh sách tăng dần hoặc giảm dần (tương đương ORDER BY trong SQL).
      + FirstOrDefaultAsync(condition): Lấy phần tử đầu tiên thỏa mãn điều kiện hoặc trả về null nếu không tìm thấy.
      + Any(condition): Trả về true nếu có ít nhất một phần tử thỏa mãn điều kiện, rất nhanh khi kiểm tra tồn tại.

  * Authentication (Xác thực) vs Authorization (Phân quyền):
    - Authentication (Xác thực - Bạn là ai?): Quá trình kiểm tra danh tính người dùng thông qua thông tin đăng nhập (Email/Password) và cấp Cookie phiên đăng nhập (app.UseAuthentication()).
    - Authorization (Phân quyền - Bạn được làm gì?): Quá trình kiểm tra người dùng đã xác thực có quyền truy cập vào tài nguyên hoặc thực hiện hành động cụ thể hay không thông qua [Authorize(Roles = "...")] (app.UseAuthorization()).
    - Lưu ý thứ tự Middleware trong Program.cs: Bắt buộc đặt app.UseAuthentication(); TRƯỚC app.UseAuthorization();.
  * Các thành phần cốt lõi của ASP.NET Core Identity:
    - IdentityUser / ApplicationUser: Lớp đại diện cho tài khoản người dùng (lưu trong bảng AspNetUsers).
    - IdentityRole: Lớp đại diện cho vai trò/nhóm quyền trong hệ thống (lưu trong bảng AspNetRoles).
    - UserManager<TUser>: Dịch vụ quản lý vòng đời người dùng (tạo user, băm mật khẩu, kiểm tra/gán/gỡ Role).
    - SignInManager<TUser>: Dịch vụ xử lý đăng nhập (PasswordSignInAsync), đăng xuất (SignOutAsync) và phát hành Cookie xác thực.
    - RoleManager<TRole>: Dịch vụ quản lý tạo, sửa, xóa và kiểm tra sự tồn tại của các Role.
