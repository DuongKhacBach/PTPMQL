- Kiến thức & Định nghĩa cơ bản:
  * Mô hình MVC (Model - View - Controller):
    - Model: Đại diện cho dữ liệu, các lớp đối tượng và quy tắc nghiệp vụ (business logic).
    - View: Giao diện người dùng (UI), hiển thị dữ liệu ra màn hình (sử dụng cú pháp Razor .cshtml).
    - Controller: Bộ phận trung gian tiếp nhận yêu cầu (HTTP Request), tương tác với Model và chọn View tương ứng để trả kết quả (Response).
  * Action: Phương thức (Method) nằm trong Controller xử lý một chức năng cụ thể (ví dụ: Index(), Details(), Create()).
  * Layout (_Layout.cshtml): Template khung giao diện dùng chung (header, menu, footer) cho toàn bộ website, giúp code giao diện không bị lặp lại.

- Kiến thức & Định nghĩa cơ bản:
  * wwwroot (Static Files): Thư mục chứa các tệp tĩnh công khai không cần server xử lý logic (CSS, JavaScript, hình ảnh, thư viện Bootstrap/jQuery).
  * CI/CD (Continuous Integration / Continuous Deployment):
    - CI (Tích hợp liên tục): Tự động kiểm tra, build mã nguồn mỗi khi có commit mới.
    - CD (Triển khai liên tục): Tự động đẩy ứng dụng sau khi build lên máy chủ/hosting.
  * GitHub Actions (.github/workflows): Công cụ tự động hóa các quy trình (workflow) theo kịch bản YAML khi có sự kiện đẩy code lên GitHub.
  * WebDeploy / MSDeploy: Công cụ của Microsoft hỗ trợ đóng gói và đồng bộ ứng dụng lên máy chủ web IIS / MonsterASP qua cổng bảo mật 8172.
  * GitHub Secrets: Nơi lưu trữ an toàn các thông tin nhạy cảm (mật khẩu FTP/WebDeploy, API Key) mà không bị lộ trên mã nguồn công khai.

  + Tùy biến định tuyến (Custom Route: /thong-tin/trang-chu).

- Kiến thức & Định nghĩa cơ bản:
  * Model Binding: Cơ chế tự động chuyển đổi dữ liệu từ HTTP Request (Form inputs, Query string, Route parameters) thành các kiểu dữ liệu và đối tượng C# tương ứng.
  * HTTP GET vs HTTP POST:
    - HTTP GET: Phương thức dùng để yêu cầu dữ liệu từ server (ví dụ: mở trang hiển thị form trống). Dữ liệu đính kèm trên thanh địa chỉ URL.
    - HTTP POST: Phương thức dùng để gửi dữ liệu từ form lên server để xử lý/lưu trữ. Dữ liệu được giấu trong phần thân (Body) của request, an toàn hơn và truyền được nhiều dữ liệu.
  * Tag Helpers (asp-for, asp-action, asp-controller): Cú pháp mở rộng của Razor trong ASP.NET Core giúp liên kết các trường input của HTML trực tiếp với thuộc tính trong Model C#.
  * Routing (Định tuyến): Cơ chế ánh xạ đường dẫn URL mà người dùng truy cập tới Controller và Action tương ứng để thực thi.

- Kiến thức & Định nghĩa cơ bản:
  * Bootstrap 5 (CSS Framework):
    - Khái niệm: Framework giao diện mã nguồn mở phổ biến nhất giúp xây dựng website chuẩn Responsive (tương thích mọi kích thước màn hình từ Mobile, Tablet đến Desktop).
    - Cách dùng cốt lõi:
      + Grid System (Hệ thống lưới 12 cột): Sử dụng .container, .row, .col-* (col-12, col-md-6, col-lg-4...) để chia bố cục linh hoạt.
      + Components (Thành phần dựng sẵn): Navbar (thanh điều hướng), Card (thẻ nội dung), Form (form nhập liệu), Button (nút bấm), Alert (thông báo), Badge, Modal...
      + Utilities (Lớp tiện ích nhanh): Căn lề (.m-*, .p-*), hiển thị Flexbox (.d-flex, .justify-content-between), màu sắc (.text-primary, .bg-light), bo góc (.rounded-3)...
    - Lưu ý quan trọng khi sử dụng Bootstrap 5:
      + Luôn đặt cột (.col-*) bên trong hàng (.row), và hàng (.row) phải nằm trong khung (.container hoặc .container-fluid).
      + Nhúng file JavaScript Bundle (bootstrap.bundle.min.js) ở cuối thẻ <body> để các hiệu ứng tương tác (như Menu thu phóng trên di động, Dropdown, Modal) hoạt động được.
      + Thứ tự nhúng CSS: Phải nhúng bootstrap.min.css TRƯỚC, rồi mới nhúng các file CSS tự viết (site.css, custom.css) để có thể ghi đè (override) style theo ý muốn.

  * Tác dụng của việc Tách file CSS và Nhúng vào Layout (_Layout.cshtml):
    - Tái sử dụng & Tính nhất quán: Khai báo 1 lần tại _Layout.cshtml, mọi View con (Home, Demo, Student...) đều tự động áp dụng chung bộ nhận diện giao diện (font chữ, màu sắc, nút bấm).
    - Tối ưu hiệu năng (Browser Caching): File .css tách biệt được trình duyệt lưu vào bộ nhớ đệm (Cache), khi người dùng chuyển trang không cần tải lại CSS -> tốc độ tải trang cực nhanh.
    - Dễ bảo trì & Quản lý module: Tách bạch rõ ràng giữa site.css (reset/font chữ nền tảng) và custom.css (tùy biến màu sắc, đổ bóng, hiệu ứng). Khi cần đổi giao diện toàn web chỉ cần sửa 1 nơi duy nhất.
    - Thuộc tính asp-append-version="true": Tự động sinh mã băm phiên bản (hash version) giúp trình duyệt tự cập nhật file CSS mới ngay khi có chỉnh sửa mà không bị dính cache cũ.

  * Thư mục wwwroot (Web Root):
    - Khái niệm: Thư mục gốc công khai duy nhất lưu trữ các tệp tài nguyên tĩnh (Static Files: CSS, JS, hình ảnh, thư viện bên thứ 3).
    - Tính bảo mật: Toàn bộ mã nguồn C#, Controllers, Models, Views nằm ngoài wwwroot đều được máy chủ bảo vệ an toàn, người dùng không thể truy cập trực tiếp qua URL.
    - Cấu hình bắt buộc: Cần có app.UseStaticFiles(); trong Program.cs để máy chủ kích hoạt tính năng phục vụ tệp tĩnh từ wwwroot.

  * Khái niệm ORM & Entity Framework Core:
    - ORM (Object-Relational Mapping): Kỹ thuật ánh xạ bảng cơ sở dữ liệu thành các lớp (Class) đối tượng trong C#, giúp thao tác dữ liệu qua code mà không cần viết câu lệnh SQL thủ công.
    - Entity Framework Core (EF Core): Thư viện ORM chính thức và mạnh mẽ nhất cho nền tảng .NET.
    - CRUD: 4 thao tác quản lý dữ liệu cốt lõi (Create - Tạo, Read - Đọc, Update - Cập nhật, Delete - Xóa).

[TUẦN 6]
- Ngày cập nhật: 17/09/2026
- Nội dung tóm tắt:
  + Cấu hình kết nối Cơ sở dữ liệu SQLite trong dự án ASP.NET Core MVC theo phương pháp Code-First.
  + Thực hiện quy trình 7 bước chuẩn:
    * Bước 1. Cài đặt các package cần thiết cho project:
      - Cài đặt dotnet tools toàn cục: dotnet-aspnet-codegenerator, dotnet-ef.
      - Cài đặt các thư viện NuGet: Microsoft.EntityFrameworkCore.Design, Microsoft.EntityFrameworkCore.Sqlite, Microsoft.VisualStudio.Web.CodeGeneration.Design, Microsoft.EntityFrameworkCore.SqlServer, Microsoft.EntityFrameworkCore.Tools.
    * Bước 2. Thiết lập kết nối CSDL trong appsettings.json:
      - Khai báo ConnectionStrings với chuỗi kết nối "DefaultConnection": "Data Source=App.db; Cache=Shared".
    * Bước 3. Tạo file ApplicationDbContext:
      - Tạo thư mục Data và lớp ApplicationDbContext kế thừa DbContext.
      - Khai báo DbSet<Person> Person { get; set; } để ánh xạ bảng dữ liệu vào CSDL.
    * Bước 4. Cấu hình kết nối CSDL trong Program.cs:
      - Đăng ký DbContext với DI Container qua builder.Services.AddDbContext<ApplicationDbContext>(...).
      - Chỉ định sử dụng SQLite qua options.UseSqlite(...).
    * Bước 5. Tạo class trong Model:
      - Tạo lớp Person trong thư mục Models với các thuộc tính: PersonId (khóa chính [Key]), FullName, Address.
      - Sử dụng Data Annotations ([Table("Persons")]) để định danh bảng tương ứng trong CSDL.
    * Bước 6. Sử dụng Migrations để quản lý phiên bản CSDL:
      - Chạy lệnh: dotnet ef migrations add Create_table_Person để sinh mã khởi tạo bảng Persons.
    * Bước 7. Cập nhật thay đổi CSDL:
      - Chạy lệnh: dotnet ef database update để áp dụng migration, tự động sinh ra file CSDL SQLite App.db.
      - Cài đặt và sử dụng extension SQLite Viewer trong IDE để xem trực quan bảng dữ liệu.

- Kiến thức & Định nghĩa cơ bản:
  * Phương pháp Code-First:
    - Cách tiếp cận xây dựng mã nguồn (C# Class Model) trước, sau đó Entity Framework Core tự động sinh ra cấu trúc bảng và cơ sở dữ liệu (Database) tương ứng.
  * DbContext & DbSet:
    - DbContext: Cầu nối trung gian đại diện cho phiên làm việc với cơ sở dữ liệu, quản lý theo dõi thay đổi (Change Tracking), lưu trữ và truy vấn dữ liệu.
    - DbSet<TEntity>: Đại diện cho một tập hợp thực thể (bảng) trong CSDL, cho phép thực hiện các thao tác CRUD (Create, Read, Update, Delete).
  * Data Annotations:
    - Các thuộc tính đặt trước class/property (như [Table], [Key], [Required], [MaxLength]) để cấu hình quy tắc và ràng buộc dữ liệu cho bảng CSDL trực tiếp trên Model.
  * Connection String (Chuỗi kết nối):
    - Chuỗi thông số cấu hình cung cấp cho ứng dụng biết loại CSDL, vị trí lưu trữ file (Data Source=App.db), và chế độ chia sẻ bộ nhớ (Cache=Shared).
  * EF Core Migrations:
    - Cơ chế quản lý các phiên bản thay đổi của cấu trúc CSDL theo thời gian (tương tự như Git cho CSDL), giúp đồng bộ và nâng cấp CSDL an toàn mà không làm mất dữ liệu.
